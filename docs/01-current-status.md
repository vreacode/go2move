# 当前状态与遗留问题

## 已完成

- Dashboard 三层架构：Agent、Server、Web 前端；
- WebRTC 实时视频、模型启动/停止/重启、事件和快照；
- 建图、保存地图、启动导航、打开 RViz 的白名单工作流；
- 地图列表、yaml/pgm 查看；
- 底盘安全桥：dry-run/real、锁定、人工接管、急停、watchdog；
- 默认使用 /cmd_vel_nav，并按阿克曼语义处理左右转；
- 默认启动脚本已尽量避免重复拉起 base、IMU、雷达和 RViz。

## 已确认的实机问题

1. nano_rtsp_detect.py 可能占用约 84%–99% CPU，必须和导航/录制组合测试；
2. 旧版导航脚本会重复启动多套 ROS 节点，造成 CPU 竞争；
3. 建图脚本还需要更强的 SLAM ready 检查；
4. 阿克曼“前进左转/前进右转”需要在架空状态下确认前轮偏转、回正和急停；
5. 桌面录屏目前是 x264 fallback，不是 Jetson 硬件编码链。

## 下一步验证顺序

1. 只启动底盘、雷达和 IMU，确认 ROS topic/node ready；
2. 低负载运行 Dashboard，记录 CPU、内存和关键 topic 频率；
3. 架空车辆验证前进、后退、前进左转、前进右转、停止、急停；
4. 单独验证建图 readiness 和保存地图；
5. 单独验证导航 preflight，再叠加视觉模型；
6. 每次联调保存日志、配置变更和可复现命令。
