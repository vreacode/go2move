# Go2 实时行人检测与跟踪

当前阶段完成视觉链路：机器狗相机 → YOLO 行人检测 → ByteTrack → 绘制框和 ID → 终端输出原图框坐标。
后续任务是结合固定人物特征、深度、相机外参和机器狗地图位姿，报告目标的地图位置。
当前输出的 ID 是本次运行的轨迹号，bbox 是图像像素坐标，不是地图位置或身份确认。

截至 2026-10-16，当前实验只考虑单人走动、转身和肢体局部遮挡。
多人真人交错遮挡实机测试暂不执行；保留多人合成检测框的代码回归。
当前不引入 ReID，无图形窗口，保留 JPG、AVI 和结构化记录。

## 在本机运行

在仓库根目录执行。相机服务通过官方 SDK2 VideoClient 持续采集，跟踪脚本直接读取它提供的原始 JPEG：

```bash
systemctl --user start go2-native-camera.service
python3 -u 'person_track(1).py' --source go2
```

本机是 Jetson，已有 YOLOX-Tiny TensorRT FP16 引擎和官方 ByteTrack 依赖。
默认自动选择这些组件，无须安装 torch 或修改现有 ROS/模型环境。
YOLOX-Tiny 是这里使用的 YOLO 检测器；它只返回 COCO 的 person 类。

网页预览服务已删除。默认只打印终端日志、保存标注视频和最新标注图像。
按 Ctrl+C 停止跟踪；已启动的相机服务继续运行。脚本不会调用运动、地图导航或语音接口。

只做一次有限验证：

```bash
python3 -u 'person_track(1).py' --source go2 --max-frames 30
```

不使用 OpenCV 图形窗口，`--show` 参数及窗口调用已删除。
可以查看输出目录里的视频和 `latest.jpg`，Ctrl+C 停止运行。

本机直接使用系统 `/usr/bin/python3`（Python 3.8.10），不需要 Miniconda 或 conda 环境。
OpenCV 4.2.0、NumPy 1.17.4、TensorRT 及官方 ByteTrack 依赖已可用。
`-u` 让终端及时输出日志。检测推理需要能够访问 Jetson GPU。

## 视频和其他相机

```bash
python3 'person_track(1).py' --source file:/path/to/people.mp4
python3 'person_track(1).py' --source usb:0
```

视频不循环，标注视频保留原视频帧率和图像尺寸。Go2 默认按已有采集服务的 5 FPS 工作；若调整了服务采集帧率，同步指定 `--fps`。
`--read-timeout` 用于等待 Go2 文件采集器的新帧，不控制 OpenCV 的 RTSP 网络读取超时。

普通电脑上的 Ultralytics YOLO 路径：

```bash
python3 'person_track(1).py' --source file:/path/to/people.mp4 \
  --backend ultralytics --model /path/to/yolov8n.pt --device cpu
```

该路径需要独立环境中的 torch、ultralytics 及其跟踪依赖，并使用带 COCO person 类的检测权重。
仍采用 ByteTrack，检测和跟踪分别调用，每帧更新同一个跟踪器。该环境在当前 Jetson 上未安装，未进行模型推理实测。

## 输出

终端默认每帧打印全部当前已确认轨迹：

```text
帧000013 | 目标ID=1 | bbox(x1,y1,x2,y2)=(695, 4, 1364, 1051) | conf=0.905
```

同时打印累计统计；结束时还打印每个 ID 的统计。以下数字为合成回归序列示例：

```text
[统计] 单ID最大连续存活帧数=18(含遮挡缓存) | 最大连续观测帧数=9 | 总ID切换次数=0 | 多轨迹歧义帧数=0
```

坐标原点在原图左上角，x 向右，y 向下。框坐标与保存的视频分辨率一致。
ByteTrack 可能需要连续两帧才能确认一个新轨迹；此时终端会显示检测框数量，但不会编造 ID。

每次运行创建独立目录 `runs/track/日期_时间_进程号_后缀/`，包含：

- `person_track.avi`：带框、ID 和人数的 MJPG 视频。
- `latest.jpg`：最新的标注图像。
- `tracks.jsonl`：逐帧时间戳、图像尺寸、检测数量和已确认轨迹。每个人包含 `track_id`、`bbox`、`confidence`，另记录 `cached_track_ids` 和 `tracking_metrics`。
- `summary.json`：运行状态、帧数、实际使用的 `tracker_config`、累计 `tracking_metrics` 和每个 ID 的统计。

结束或异常时，JSONL 写入 `event=stopped`、原因和空 `people` 列表，便于下游停止使用目标。
图像输入拒绝过期帧、重复采集时间戳和 JPEG/状态哈希不一致的帧；采集器停止时会超时报错。

`--no-save-video` 可以减少磁盘写入，保留最新图像和结构化记录。
`--log-every 5` 可以降低终端输出频率；JSONL 仍记录每个处理帧。

## 单人关联参数

默认检测阈值 `--conf 0.1` 保留低置信度候选供 ByteTrack 二次匹配。
当前单人配置与前一版视觉脚本对比如下：

| 参数 | 前一版 | 当前单人配置 | 目的 |
|---|---|---|---|
| `--lost-seconds` | 3 | 6 | 约 5 FPS 时保留约 30 个输入帧的遮挡缓存 |
| `--match-thresh` | 0.8 | 0.9 | 放宽关联代价上限，容许转身或局部遮挡导致的框重叠减少 |
| `--track-thresh` | 0.25 | 0.20 | 较低置信度候选也可参加包含缓存轨迹的第一阶段匹配 |
| `--new-track-thresh` | 随高分阈值计算，原为 0.35 | 独立保持 0.35 | 放宽关联时仍保留新轨迹创建门槛 |
| 关联置信度融合 | 开启 | 默认关闭 | 单人框关联不再被转身时降低的置信度进一步惩罚 |

通过 `--fuse-score` 可重新开启关联置信度融合。这是面向单人的关联取舍，不是所有场景通用的最佳参数。
实时输入跳帧时，按采集时间差老化轨迹；缓存过期后仍会换号，不强制给新框分配旧 ID。
缓存中的预测框不绘制，也不放进 `people` 当作实际检测到的人。
`--iou` 控制检测 NMS，不是跟踪器的匹配阈值。

ByteTrack 通过运动预测和框关联保持 ID，无法保证长时间遮挡、快速出入画面、严重运动模糊时仍保持身份。
当前不引入 ReID。寻找固定特征人物和计算地图位置仍需要后续目标筛选、深度/测距与坐标变换。

本机适配器新增可选的新轨迹阈值及置信度融合控制；既有 `person_search` 服务调用适配器时的默认参数保持原值。
修复官方 ByteTrack 本地副本中的高分阈值边界：恰好等于阈值的检测进入高分关联，避免被高低两阶段同时排除。

## 统计口径

- `max_alive_frames`：一个 ID 在连续处理帧内保持已确认、正在跟踪或仍在遮挡缓存中的最大帧数。缓存过期后停止累计。
- `max_consecutive_observed_frames`：同一 ID 在相邻处理帧都有实际匹配框的最长连续帧数；空帧会中断连续观测，但不一定导致换 ID。
- `total_id_switches`：在单人实验假设下，前后各仅有一个确认 ID 时，该 ID 改变就加 1。首次出现不计切换，中间空帧不清除上次 ID，也不单独增加切换次数。
- 多个确认 ID 同时出现时，累计 `ambiguous_frames`，清除 ID 比较参照，不猜测哪个轨迹对应原来的单人。
- 没有确认轨迹时 `has_confirmed_tracks=false`，终端明确提示不能评价 ID 稳定性；不能把“零切换”当作跟踪成功。

以上帧数按实际处理帧统计，不把跳帧老化时补偿的空更新记作观测帧。
存活帧数含缓存，不能单独用来宣称可见跟踪更连续，需要同时查看连续观测帧数、实际观测数量和切换次数。
切换统计依赖现场只有一个待测人员的假设，不等同于有人工身份真值的标准 MOT IDSW，也不能用于多人身份正确率评价。

## 单人操作测试与验收基线

以下为当前实验的内部验收标准，不是行业通用指标。测试前固定参数，结果出来后不能为通过验收而临时放宽阈值。
机器狗保持原位，只有一名测试人员入镜，以全身或主要躯干清晰可见为准，避免靠近镜头只拍到腿。
当前未使用 ReID；完整离场或连续完全遮挡超过 6 秒不属于本轮 ID 保持验收范围。

先运行 23 项代码回归，再做 30 帧相机/推理/文件输出功能检查；空场景的功能检查不算单人跟踪验收通过。
确认现场人员准备好后，进行一轮约 60 秒的操作测试：

| 时间 | 现场动作 | 核对重点 |
|---|---|---|
| 0–10 秒 | 正面站稳，身体清晰入镜 | 能在 2 秒内建立 ID，框应对应人体 |
| 10–25 秒 | 缓慢左右走动、往返，保持在画面中 | 同一 ID 持续跟踪，不跳到椅子或背景 |
| 25–40 秒 | 缓慢转为侧身、背身，再转回正面 | 框大小变化时不换 ID |
| 40–55 秒 | 用手臂或椅背制造局部遮挡，每次 1–2 秒，做 3 次 | 遮挡解除后 1 秒内恢复实际观测，仍是原 ID |
| 55–60 秒 | 回到正面站稳 | 核对最终 ID，正常结束并写出统计 |

验收以 JSONL 的采集时间戳和标注视频共同核对。AVI 使用固定输出帧率，处理时跳过采集帧会使播放时长短于现场时长，因此不能直接把 AVI 播放秒数当作动作发生时间。
每次试验记录人物是否确实完成动作、是否曾离开视野及是否有其他人入镜。条件未满足时记录为“试验无效/需重测”，不能把没有检测到人的零切换结果判为合格。

| 检查项 | 本轮合格基线 |
|---|---|
| 程序与输入 | 正常结束，`error=null`，没有相机超时；时间戳递增、不重复 |
| 有效测试长度 | 动作流程约 60 秒；有效采集时间跨度至少 50 秒 |
| 有效帧率 | `(处理帧数-1)/(末帧采集时间-首帧采集时间)` ≥ 3 FPS，不计模型加载时间 |
| 目标建立 | 人已清晰入镜的前提下，2 秒内有确认 ID |
| ID 稳定性 | `unique_ids=1`、`total_id_switches=0`、`ambiguous_frames=0` |
| 观测覆盖 | 人始终在视野且仅局部遮挡的有效测试段，恰有一个确认框的帧占比 ≥ 90%；该比率是观测覆盖率，不是有人工真值的检测召回率 |
| 连续性 | `max_alive_frames` ≥ 有效处理帧的 90%；同时在静止段至少连续 5 秒有实际人体框，不能只靠缓存延长存活 |
| 局部遮挡恢复 | 3 次 1–2 秒局部遮挡后，均在解除后 1 秒内恢复原 ID；需要依据现场动作和录像人工核对 |
| 框的正确性 | 视频中框持续对应测试人员，没有跳到背景或其他物体；需人工核对 |
| 结果文件 | `latest.jpg` 可解码，AVI 全部可解码，视频帧数与 JSONL 的 frame 记录数一致，summary/终止记录齐全 |

自动日志检查满足只是初步通过；动作完成情况、框是否对应人体、每次遮挡恢复需人工复核。
先做一轮试测，正式验收建议按相同流程重复 3 轮，全部达到基线后标记“单人场景验收合格”。
最长连续存活帧数包含遮挡缓存，必须同时检查实际观测数量、连续观测时间和换号次数。
本轮不启动图形窗口或网页预览，不执行多人真人交错遮挡试验，也不测试运动、导航、语音或地图位置报告。

首段约第 18.3–23.3 秒无确认观测，共约 5 秒，随后第 110 帧分配 ID 5；抽查第 90 帧时画面中已看不到人。
第 80 和 110 帧显示人体靠近镜头、主要剩腿部且被画面边缘截断，因此不能把这次换号归因于始终在视野内的局部遮挡。
补录中确认到背身及椅背局部遮挡；第 121–129 帧约 1.815 秒无确认框，第 130 帧恢复原 ID 2。
这表明该次遮挡缓存维持了 ID，但不等同于“3 次遮挡解除后 1 秒内均恢复”的逐次人工验收已经通过。

补录首尾分别有约 5.9 秒和 11 秒无确认观测，抽查第 230 帧是空画面。
首次至末次确认观测区间的覆盖率为 95.36%，只作为补充描述；不替代预先规定的整段 90% 门槛。
首段的转身/遮挡提示偏晚，另做补录；两段不能合并当成一轮严格同步验收，进程间的 ID 编号也不能直接比较。

结论：**本轮尚未取得单人场景的完整合格验收记录**。首段换号及单 ID 存活占比不足；补录整段覆盖率和存活占比不足，且活动范围/动作时序未完全满足流程。
