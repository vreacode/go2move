# 按系统说明书推进项目

《智能网联汽车整车技术科创系统》列出 5 个实训模块和 30 个技能点。结合当前实际系统，建议按以下阶段推进，每阶段都有可验收结果。

## 阶段 0：版本化和安全基线

- 建立 GitHub Private 仓库；
- 固定板卡、ROS2、相机、雷达、IMU 和底盘的设备清单；
- 为每次实机测试记录 commit、配置版本、地图名、模型名、CPU 和 topic 频率；
- 保持控制默认 dry-run/locked，不上传密钥和模型权重。

验收：新终端能根据 README 找到代码、文档和启动入口，且仓库扫描不到 .env、token、录像和权重。

## 阶段 1：整车通信与传感器基线

- 底盘：确认 /cmd_vel_nav、/odom、底盘状态反馈；
- 雷达：确认 IP、2368/2369 端口、/c16/lslidar_point_cloud 频率；
- IMU：确认 /imu/data_raw 和 /imu/data 的频率、frame_id、时间戳；
- 相机：确认 RTSP 可持续读取和实际分辨率；
- 记录 TF、坐标系和时间同步状态。

验收：形成一份“传感器健康检查”脚本或报告，所有输入都有明确 topic、频率和坐标系。

## 阶段 2：建图、定位、导航闭环

- 先完成点云转 /scan 的 readiness 检查；
- 再完成 SLAM 建图和地图保存；
- 使用固定地图完成 Nav2 preflight；
- 让 RViz 负责初始位姿、TF、costmap 和路径调试；
- 最后才接入 Web Dashboard 的工作流按钮。

验收：同一地图可重复启动导航，记录启动时间、定位稳定时间、路径跟踪误差和异常日志。

## 阶段 3：视觉感知与事件闭环

- 先单模型验证 helmet/fall/smoke/danger 的输入输出；
- 对每个模型统计 FPS、CPU/GPU、置信度和误报；
- 增加事件冷却、快照和日志的自动化测试；
- 评估检测模型和 Nav2 同时运行时的 CPU 余量；
- 后续再做点云/视觉目标融合，不先扩展前端 3D 调试界面。

验收：给出每个模型的最小测试集、准确率/召回率或至少误报漏报记录，并明确演示模式的负载上限。

## 阶段 4：底盘控制和安全功能

- 架空状态完成方向和急停验证；
- 低速封闭场地验证前进左转/右转，不做横移；
- 增加控制超时、导航运行互锁和人工接管记录；
- 再推进 AEB、障碍物停车/避障、循迹控制。

验收：每个动作都有触发条件、最大速度、停止条件和回滚方案，任何异常都能急停。

## 阶段 5：整车测试与科研扩展

按说明书依次扩展：多传感器标定、障碍物检测、Pure Pursuit、PID 速度控制、多传感器融合、AEB、红绿灯响应、V2X 和 CARLA 在环。每次只推进一个可测功能，避免同时改动感知、规划和控制三条链路。
